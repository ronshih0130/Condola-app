# B-009 — Bank reconciliation

Scope: CSV retransmission dedupe, explicit manual matching and rejection of suggestions.

Out of scope: automatic banking access or silently resolving ambiguous candidates.

UI/copy: CAP-M-10/23, J3.5 and brand-v2 tables.

Data/migrations: inspect import identity constraints; propose `<unique_timestamp>_b009_bank_match_decisions.sql` for unique source keys and append-only decisions.

Acceptance:
- Given the same file twice, when imported, then no payment is registered twice.
- Given multiple/equal/no candidates, when processing, then no automatic financial status change occurs.
- Given an authorized manual match/rejection, when confirmed, then actor, reason code and source are retained. Reasons are `confirmed_amount`, `wrong_payment`, `duplicate`, or `other`. Any other text is rejected. A stored non-code is rewritten to `other`.
- Given concurrent approval, when both execute, then only one effective match exists.

Tests/evidence: sanitized regional CSV fixtures, concurrency and cross-org denial under `/workspace/e2e/results/B-009/`.
