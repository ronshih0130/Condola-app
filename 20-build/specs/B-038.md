# B-038 — Repair pushes

Scope: committed repair status/result and applicable approval events to authorized tenant/owner recipients, using shared delivery/quota/fallback.

Out of scope: internal notes, unrestricted photos, secrets or real messages.

UI/copy: LINE access plan, approved repair copy and brand-v2 repair/approval templates.

Data/migrations: reuse shared events; propose `<unique_timestamp>_b038_line_repair_event_types.sql` only if necessary for additive constraints.

Acceptance:
- Given tenant-visible repair change, when queued, then tenant receives only authorized summary/deep link.
- Given owner approval context, when recipient is selected, then current property authority is checked.
- Given event replay/version change, when dispatched, then dedupe prevents duplicate same-version notification while preserving new events.
- Given revoked authority or quota failure, when worker executes, then protected payload is withheld and appropriate Email fallback is recorded.
- Given global kill, when processed, then no new LINE push occurs.

Tests/evidence: recipient matrix, payload minimization, concurrent claims and fallback under `/workspace/e2e/results/B-038/`.
