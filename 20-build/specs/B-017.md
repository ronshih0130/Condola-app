# B-017 — Custom role permissions

Scope: close M-54’s view-only gap with custom-role assignment and server-enforced permissions, preserving minimum-privilege constraints.

Out of scope: weakening mandatory privacy restrictions or giving users permissions they cannot grant.

UI/copy: inventory M-54, CAP-P-12 and brand-v2 team/permission patterns. No dedicated canonical custom-role CAP exists.

Data/migrations: propose `<unique_timestamp>_b017_custom_roles.sql` for org-scoped roles, permission assignments and audit.

Acceptance:
- Given a permitted Admin, when creating/assigning a role, then only supported permissions can be granted.
- Given last-admin/self-lockout or privilege escalation, when requested, then it is rejected.
- Given Accountant or portal identities, when opening protected photos/full-company audit, then mandatory restrictions still apply.
- Given changed permissions, when a direct API request occurs, then server enforcement matches UI.

Tests/evidence: permission matrix, stale sessions, cross-org role references and escalation attempts under `/workspace/e2e/results/B-017/`.
