# B-024 — Vendor job UI

Scope: single-job accept/reject/proposed time, company-confirmed appointment, photos and completion reason; enforce B-013 approval state.

Out of scope: token-derived history access or auto-closing on vendor submission.

UI/copy: CAP-V-01/02/03 and brand-v2 vendor-job/responsive states. Use “待屋主核准” and “已回報，待公司核對”.

Data/migrations: reuse B-013; propose `<unique_timestamp>_b024_vendor_completion_reason.sql` only if reason/response fields are missing.

Acceptance:
- Given pending approval, when starting/completing via UI or direct API, then both are denied.
- Given rejection, when reason is supplied, then original repair remains.
- Given no after-photo, when completing, then reason is mandatory.
- Given completion submission, when accepted, then company review is still required.
- Given revoked/expired token, when opening photos/job, then access is denied.

Tests/evidence: state matrix, photo leakage and 44px controls under `/workspace/e2e/results/B-024/`.
