# B-020 — Tenant settings

Scope: tenant profile, password/session controls, notification preferences and trackable data requests.

Out of scope: silent account deletion, consent-text changes or disabling mandatory service/legal notices without an approved rule.

UI/copy: CAP-T-13 and brand-v2 account/settings patterns.

Data/migrations: propose `<unique_timestamp>_b020_portal_preferences_requests.sql` for org/context-scoped preferences and request status if absent.

Acceptance:
- Given tenant session authority, when revoking another session, then it becomes unusable.
- Given preference changes, when optional events are evaluated, then the current preference is respected.
- Given a data request, when submitted/retried, then one trackable request exists.
- Given forged user/org identifiers, when saving, then server ignores/rejects them.

Tests/evidence: recent-auth requirements, session revocation, preference scope and request dedupe under `/workspace/e2e/results/B-020/`.
