**What the existing barriers cover.** The runner's persistent flock is keyed by system identifier under the canonical approved PGDATA and inherited by the pinned psql child. It covers the whole normal cycle. The database advisory lock alone would not serialize cluster-wide roles. Admission requires a physically separate Linux cluster with one login, a named maintenance superuser, no other client backend, TCP listener, prepared transaction, enabled event trigger or subscription. Exclusive OS ownership and absence of independent schedulers, replication managers and privileged writers are still PE target prerequisites. No real target was examined.

The install encloses preflight, exact inputs, seal and assertions in one error-stop transaction. The seal removes the explicit service grants and checks the private owners, memberships, effective ACLs, empty tables and unchanged control hashes. The paired down locks the four private tables, compares the original sealed state before dropping, uses explicit object-level RESTRICT, and issues DROP ROLE directly. Unexpected cluster-wide ownership or ACL dependencies that PostgreSQL refuses to drop therefore roll the transaction back. There is no broad DROP OWNED, REASSIGN OWNED or CASCADE. Those safeguards are worth retaining. The receipts can claim only their scoped catalog/controls; the missing restore, real-principal, fault and business-compatibility proofs remain F01–F10 NOT_RUN.
