# B018 browser egress guard v2

Source draft only; no socket, HTTP proxy, browser or database has been started. The module requires independent review, a new lock and explicit runtime authorization. It carries forward the exact fixed upstream, literal URL classifier, forced browser proxy launch validation, branded handle and service-worker blocking from v1. It is not an OS firewall and does not establish non-HTTP isolation.

All ordinary HTTP exchanges are tracked before upstream socket assignment through incoming body end and close, upstream request finish and close, incoming response end and close, and client response finish and close. Incomplete downstream response immediately fails and destroys the upstream. Teardown checks pending HTTP and HMR requests and both socket sets; it waits for server closure and every tracked terminal and rejects with `egress-quarantine` on a bounded drain failure. Any unfinished transport at planned shutdown is fatal, never suppressed. Late error events remain fatal and the parent must preserve the final post-drain snapshot and event stream. HMR has explicit request and both-peer closure, with unexpected peer closure while contexts remain active fatal. It makes no claim about WebSocket frame delivery.

Connection tokens other than close, keep-alive or upgrade are rejected on both legs. All upstream enforced or report-only CSP headers and all informational responses fail closed; the guard does not claim a positive witness for a blocked response. This conservative zero-policy-only scope may make actual app evidence unavailable. Redirects remain restricted to the fixed origin. The private per-exchange HTTP response event is emitted from the upstream original headers before any filtering, so the future collector can bind its own safe policy evidence. A separately reviewed correlation algorithm is needed before it can support any document verdict.

The parent registers exactly one `observeExchanges(callback)` before browser attachment. Each callback receives a monotonically sequenced immutable event and unique exchange ID. Request events carry method, raw URL, and ordered allowlisted original and forwarded Cookie or WebSocket key values. Response events carry upstream and actual downstream allowlisted CSP, report-only CSP, Link, Set-Cookie, Location and WebSocket accept values and status. Inconsistent protected-header projections fail closed. Rejected response events contain only original fields and explicitly say rejected. Transport and HTTP/HMR terminal events record their observed dispositions. An incomplete HTTP exchange or undrained socket cannot qualify as closed. This private callback contains sensitive data and MUST remain in memory; its trusted parent must HMAC and redact before persistence. It does not receive authorization headers, bodies, passwords or WebSocket payloads. The public `onEvent` has only sequence and fixed labels. Detachment before closure and callback failure are fatal. Exchange IDs are not browser request IDs; unambiguous browser correlation remains a separate reviewer-approved collector responsibility.

After browser launch via `proxyLaunchOptions`, attach and create contexts via the branded handle. Close contexts normally, call `beginPlannedBrowserClose()`, await browser close, then await `close()` and inspect the final snapshot. Parent supplies bounded outer process cleanup, all guard-event journaling, policy/request correlation, source and binary locks, and independent post-drain auth and financial recovery. A failed or unavailable guard remains fatal. No prior receipt is revised.

Development verification: 19 inherited URL-classification tests and 10 adversarial/positive in-memory mocked lifecycle tests, no real socket or HTTP operation. These tests cannot establish browser routing, actual TCP behavior, correct Next HMR timing or absence of unobserved transports. Independently review source and run separately authorized isolated controls before integration.
