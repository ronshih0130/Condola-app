# B018 parent integration design review

**GO to author the OFF-only bootstrap parent and its pure failure-path tests.** The ordering in design v1 is executable. A fresh source lock can exist before warm-up, an observation freeze can bind the actual generated asset afterwards, and a parent receipt can bind the completed journal later. The first run can establish a bootstrap-only result even if its financial aggregate remains pending. There is no approval here to launch it.

Four acceptance conditions matter before a source freeze.

1. **Own the bytes being measured.** Reserve the clone name, run directory, loopback listener and a fresh private build directory, or an independently verified exclusively leased build tree with known provenance, before starting children. Keep source candidates 1c8fd07 and current documentation HEAD separately identifiable. Pin the exact Next dependency files used for mapping. In next dev the hot reloader runs *before* static filesystem routing (router-server.js:268–285). Confirm the exact webpack path falls through this installed handler, resolves under the actual distDir/static root and reaches serveStatic. The filesystem and static-server paths are documented in filesystem.js:137–139,469–475 and router-server.js:351–389. Reject symlinks, rewrites, alternate origins, queries other than the reviewed decimal version, and mismatched stat/content. Observe server/file generation across the measured interval, in addition to before/after digests. An observed rebuild, unstable generation, missing change coverage or ambiguous handler must invalidate affected map evidence. Make the actual enabled script response bytes and executed script independently join to the same render map. Warming a path or hashing an on-disk neighbor cannot establish serving identity.

2. **Prove error observation begins before setup and ends after drain.** Existing login supervisor.py:63 routes both server streams to DEVNULL, so an unchanged wrapper cannot establish absence of server errors. Provide a bounded, in-memory server-error observer before warm-up, with an allowlisted diagnostic vocabulary, no credential/header/body/raw stdout persistence, and a fail-closed result for lost or unclassifiable error telemetry. Include strict independent PW/CDP, HTTP, console, page-error and foreign-request events from every arm, including any explicit positive-counterpart navigation and teardown. Give input events stable local ordinals and use a sealed prefix plus a losslessly recorded tail. A cutoff race, late fatal event, abnormal browser exit or missing expected source must overturn a provisional admission. Do not interpret a successful enhanced landing Document requested by the harness as the result of the user's login or as repair of an earlier aborted Fetch.

3. **Bind recovery to actual authentication effects.** The old recovery accepts up to two new sessions and equates counts of sessions and sign-in audits. This producer has three actors in each mode. The verifier must match each committed session and sign-in effect to its measured attempt, actor, expected organization/role and consent, including failed or interrupted attempts. Use current clone database identity, run and source freeze, read-only consistent snapshots and ephemeral correlation aliases. A count ceiling changed from two to six is insufficient. Baseline and final readback cover all protected financial/control/audit tables, and only the enumerated genuine authentication effects may differ. Independent recovery should still run after any safely drained failure with a valid baseline; unknown lineage, crash ownership or incomplete recovery yields quarantine, no retry or compensating mutation. A purely anonymous warm-up may need to compile protected paths via redirects; never synthesize an authenticated session to make it succeed.

4. **Separate admission from finance and report the exit honestly.** Bootstrap-only success needs the qualified native matches, clean ordinary enabled arms, a complete tail, stable sources, normal browser-close and server drain, and a successful independent control/financial readback. Preserve rawStrict FAIL on admitted negative controls and every earlier strict FAIL. The finance result is PENDING regardless of bootstrap outcome. A future full run must perform its own fresh bootstrap and baseline. A closed browser context cannot be reused across runs. Within a separately approved full run, any transfer from an authenticated JS-disabled login must stay in memory and enter a fresh JS-enabled financial context with the same independently verified actor and current session. The old focus probe demonstrates this separation at lines 55,66,88 but persisted a session ID in its completion event; exclude that field from the new persisted journal.

Before execution, review the actual producer, parent, verifier and recovery together against the measured input/output shapes and adversarial examples. Necessary negatives include lost tail, ordinary enabled abort, unmapped or changing asset, wrong actor with the correct number of sessions, and missing server-error evidence. The setup v2, a public reversal or a new DB migration is outside this parent. This review covers the planning document alone. It does not review the classifier authored by this reviewer.
