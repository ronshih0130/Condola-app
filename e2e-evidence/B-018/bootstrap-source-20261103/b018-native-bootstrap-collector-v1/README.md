## What is captured

For all three fixed actors, the collector performs a real natural-click JS-disabled native login and a separate real ordinary JS-enabled click login; the enabled side makes a real authenticated Document visit to the landing in that same enabled context. It does not manufacture enhanced-login success or transfer a native token into the enabled side. It instruments PW and CDP separately, verifies unique matching full-URL HMAC/context/frame/loader and terminal evidence for the exact webpack request, and retains all nonmatching failures. Literal query spelling must be no query or exactly `?v=[0-9]+`; encoded characters, other parameters, credentials in the URL, fragments and normalized paths are unavailable.

Document policy evidence checks PW and CDP Document response headers/extra-info and parses the actual completed HTML response in an inert DOM in memory. It rejects nonzero/unknown policy, nonce/integrity, ambiguous base/declaration, dynamic policy or unsafe script/preload mutations. An enabled-context observer must be demonstrably installed before the asset request; uncertain event ordering is unavailable. The completed source HTML, query, raw headers, script body, cookies and nonces are never persisted. Presence counts/booleans, safe pathname and opaque keyed request tokens are journaled. The source's DOM/MutationObserver ordering and header completeness are conservative but unverified and must receive adversarial review.

The collector starts V8 precise coverage before each measured document, matches scriptParsed to actual context/frame/request, compares debugger source and enabled decoded response body SHA-256 to the frozen asset and counts conservatively nonoverlapping positive execution bytes. Native capture requires zero observed matching parsed/covered execution and never fabricates a blocked response body. Each document invokes the branded map's synchronous `beginRender` before navigation and `endRender` after matching declaration/request; returned before/after proof digests and normalized PW/CDP records are appended to the parent journal. Failure to establish byte, timing, policy or request identity is unavailable, not a positive proof. The v2 session verifier consumes one distinct SID per context; the collector calls it once after landing, then records only its opaque proof hash and a per-run keyed session alias.

## Cut, failures and close

Each side is settled; protocol barriers and a simultaneous quiet/pending check precede one synchronous normalization-and-cut section. No await occurs between the final all-context drain check, normalization of every raw failure and marking the cut. Qualified normalized PW/CDP failures retain their exact IDs/context/document/frame/loader/request token in the durable journal; unmatched failures remain fatal. Any later PW/CDP failure immediately appends a new fatal record. Console/page/HTTP/external/timeout/policy-uncertain events are fatal. The collector returns `status: CAPTURED` with a schema-shaped `evidence` only if all six sides are complete and observation cut is known; otherwise it returns `UNAVAILABLE` and `evidence: null` with sanitized journal bytes/failures. CAPTURED does **not** mean native admission or aggregate PASS; known enabled Fetch cancellations remain fatal.

Parent must write `bootstrapJournalBytes` to an exclusive immutable artifact and independently hash/read it back before issuing a separate bootstrap receipt over `digest(evidence)`. Do not modify the pre-run freeze. Keep live contexts and event listeners in memory for any later separately authorized phases. After those phases, await `closeContexts()`, require its result true, collect `getAllFailures()` only after the close/drain barrier, and independently prove browser `close()` and server ownership/drain. Before stopping the still-owned server, parent must await `webpackMapHandle.sealWhileServerOwned()` and require `LIVE_CONTROLS_VERIFIED`; after server drain it must require `verifyDiskAfterParentDrain()` returns `DISK_READBACK_VERIFIED`. Failed/incomplete stages mean nonzero/quarantine; never infer browser process closure from Node group alone. Parent performs independent financial/control recovery and only its final receipt can feed the kernel aggregate. Raw bootstrap failures remain preserved, and any later enabled/financial failure is fatal. No post-drain verification, build, UI or finance workflow is implemented here.
