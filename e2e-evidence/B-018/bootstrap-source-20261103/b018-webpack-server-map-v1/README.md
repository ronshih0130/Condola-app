# B018 webpack server mapping producer v1

This source-only component supplies evidence for one compiled file in one isolated default Next 15.5.28 webpack development server. Its sole origin is the existing loopback port 43156 and its sole asset is /_next/static/chunks/webpack.js. It supports the exact path with no suffix or with one literal decimal version parameter, bounded to 64 ASCII digits. All other spellings, duplicates, fragments, escapes, ports and origins fail closed. A browser grant or financial verdict is outside this component. The real HTTP reader, process lookup, watchers and filesystem producer have not been exercised against a live server. The 17 local Node tests replace those interfaces in memory.

## Parent integration

1. Before launching any child, the parent independently freezes the approved decision, tested app candidate and working bytes, the complete dependency installation, Node/browser/tool binaries, network guard, producer and collector. Parent creates a new private run directory and a new private application directory inside it, copies its pinned application tree there and verifies the files used to load Next. It may use a separately read-only, hash-verified dependency tree. The application copy has its own fresh .next output. Only the owned server writes that build tree. There must be no overlay, alternate Next binary, custom proxy, plugin, rewrite, resolver hook or unmeasured environment override. An additional writer or ambiguous dependency resolution is UNAVAILABLE. Keep the immutable source lock on trusted parent storage. Verify its raw digest independently and reject ambiguous or duplicate JSON keys in its writer/reader before passing it to the producer.

   The parent source lock contains a webpackMapPlan object with version 1, candidate (40 lowercase hex), run (12 lowercase hex), absolute canonical runDir ending in run-<run>, appRoot exactly runDir/application, origin, pinsSha256 (the exact source-pins.json digest) and decisionSha256 (the approved note digest). The directories must be owned by the current user and private. The run field is the same string used for document URL HMACs. The lock has no field for a future compiled digest. The producer re-reads the exact original lock throughout.

2. The supervisor launches the pinned Node 20 CLI in the application directory in a fresh group with the argv used by the original local diagnostic, using next dev -p 43156 -H 127.0.0.1, no turbo argument. Supply the actual group leader from the trusted spawn, not from page data. The adapter checks the exact CLI command (Homebrew Node 20 or its real path), one IPv4 loopback listener, parent/child relationship, process group, titles, start times and working directories. It records two local process IDs and start times. The independent parent still owns prelaunch port checks, guarded environment, restart detection and all child drain/teardown.

3. After the independently bounded warm-up and before any measured browser document, the trusted Node collector parent calls await openWebpackMap({sourceLockFile,sourceLockSha256,serverGroup,hmacKey}). The key is the same fresh 32-byte Buffer used by the collector, never serialized, passed on argv or shared with site code. Initially the handle returns status PROVISIONAL or an UNAVAILABLE result with a fixed reason. The branded live handle is from this exact module instance. A serialized JSON object cannot substitute for it. The future parent can run its trusted Node collector in the Python supervisor's owned child group and transmit the ephemeral key over a private channel, or create it in that Node child. It must retain the live handle through the seal and readback phases. If the Python parent performs the server shutdown while Node stays alive, coordinate those two points over a private IPC pipe. Do not reap the Node owner of the guard before final readback. Abrupt loss of this process makes the generation unavailable.

4. The producer rehashes each checked-in source binding. It reads the concrete regular webpack file using no-follow, fstat/lstat identity, link count one, stable size/times and bounded exact bytes. Watches cover the file, its named ancestor chain and the application entry in the private run directory. The generation includes listener identity, asset stat and owned app/build/static/chunks directory identities and change times. A content change, file or directory replacement, unknown watch event or intervening directory metadata change cancels the proof, even if the final bytes happen to match. Other updates in a directory can conservatively invalidate the run. It requires enough warm-up to stabilize this narrow directory chain. macOS notifications alone do not prove continuous observation. The ownership, file/ancestor metadata and pinned immutable source assumptions are all required.

5. The producer sends two direct, unauthenticated static GETs to the exact listener after warm-up and again during live sealing. It compares complete, bounded, identity-encoded JavaScript bodies, one path-only and one fixed decimal-version control, with the compiled file. It never follows a redirect, sends a cookie or accepts a partial transfer, Set-Cookie or ambiguous response. These are labeled parent controls. They do not stand in for a browser loading or executing the script. The source's pathname-only resolution plus these finite controls supports the reviewed decimal class. A native blocked request has no actual network response body. The independent collector must still establish the enabled real response digest, V8 execution, exact declarations, policy, actor, session, route and failure ledger for each pair.

6. The output in runDir/webpack-map contains the exact private compiled byte snapshot, mapping-proof.json, asset-map.json and a separate observation-freeze.json. Files are created exclusively, fsynced and read back. The map has the exact existing classifier fields. assetMapSha256 is the canonical object digest; mapFileSha256 is the digest of file bytes. The receipt ties these to the original sourceLockSha256 and actual serverGeneration. Parent overlays only this verified observation-time information into the classifier freeze. A recorded failure may leave partial immutable artifacts; their presence never establishes provisional or final success.

7. Before issuing each measured login or landing document navigation, call handle.beginRender({context,document}). After the actual declaration/hop is correlated, call handle.endRender({context,document,frame,loader,rawUrl,fullUrlToken,declarationSha256}). Both are synchronous. Contexts are ctx1 through ctx6. Each has one context-login and one context-landing document, actual frame alias fN and loader alias lN. Each call verifies source, owner, generation, bytes and stat. The end recomputes HMAC-SHA256 over [run,context,document,frame,loader,rawUrl] joined with NUL and rejects reuse and mismatches. It persists only safe aliases, hashes, query class, stat and scoped observation references. The source declaration digest must be from the separately reviewed collector's actual document evidence. The adapter does not attest to declarations or policy by itself. A duplicate, omitted scope or any capture error invalidates sealing.

   beginRender returns context, document, generation, beforeProofSha256. endRender returns generation, mapSha256, compiledSha256, queryKind, context, document, frame, loader, fullUrlToken, declarationSha256, beforeProofSha256 and afterProofSha256. The collector must compare these with its own evidence and retain both proof hashes in the parent's journal. Never pass a caller-provided verified flag into the classifier.

8. After all measured observations and normal awaited browser close, keep the same server owned and call await handle.sealWhileServerOwned(). Require LIVE_CONTROLS_VERIFIED. Parent then stops the server, independently checks every required group drained, and calls handle.verifyDiskAfterParentDrain(). Require DISK_READBACK_VERIFIED. This last function verifies disk/source evidence and intentionally makes no process-drain claim. The supervisor must check an actual drain witness independently. Preserve all earlier failures and late events. The disk result cannot revive an unqualified bootstrap. On a failure or uncertain ownership, call handle.quarantine(), preserve partial artifacts, and run the parent’s independently authorized read-only recovery when safe. The parent owns durable outer quarantine if the process dies or artifact writes fail. There is no automatic retry.
