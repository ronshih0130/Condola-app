## Data and authorization boundaries

The reader uses only fresh read-only repeatable-read transactions on existing tables. It positively validates the actual endpoint, major version 16, owned database, role, read-only mode and row_security=off (insufficient access must error). It binds cluster identifier, database OID/name and postmaster start at microsecond precision across phases. It repeats the target-generation check after the fresh admission queries. All ordinary tables, partitions, partitioned roots and materialized views in public/app/auth are enumerated; a foreign table makes the scan unavailable. SELECT FROM ONLY visits physical children exactly once. Required financial, utility, auth, event and consent tables must be present. Every column of every non-exception row, including auth.users/profiles.updated_at, enters a domain-separated HMAC of the native PG16 record_send bytes. Array dimensions, lower bounds, element type, null markers and values enter the binary record. Column types and the recursively used element/range send functions are catalog-checked before scanning. Unknown domains/types, unavailable send support, unsupported encoding or insufficient rights fail the snapshot. Coverage includes pinned built-in scalar senders, native enums, supported built-in ranges, arrays of accepted elements and the linked citext extension backed by internal textsend. The two special tables also get typed binary commitments. A sorted multiset of tags and its count preserve duplicates. Catalog and all control values are bound separately. No sequence advancement, DDL equivalence, network isolation or whole-server proof is claimed.

The two separately reconciled tables are public.auth_sessions and public.audit_log. All old audit IDs and full rows must survive exactly. Additional audits must be two canonical sign_in inserts per actual actor in the measured window. primaryOrg uses earliest active membership first, else earliest unarchived contact. If earliest ties resolve to different orgs, this finite proof declines attestation. No portal-selected org overrides this audit rule. Each new session must match an initial verifier HMAC, distinct SID and independently witnessed token hash, exact actor, known schema, bounded source User-Agent and absent or local-loopback IP. IP class is checked; remote addresses and foreign values fail. The six TTLs must be compatible with the finite 12-hour non-remembered path, including concurrent touches where greatest() retains a later expiration than last_active_at plus twelve hours. The authenticated original expiry must not exceed the final session expiry; the fresh verifier expiry must agree with that recovered row. The readback inherits the same database timezone/ISO DateStyle as verifier v3 when obtaining the original created_at spelling. Incompatible spelling fails original HMAC verification. Offset-aware microsecond comparisons preserve offsets and fractional seconds. The check verifies a compatible interval, not each intermediate touch.

A newly constructed instance of the exact accepted session verifier rechecks each actor against fresh DB snapshots after the initial protected-data scan. This reuses canonical consent, live organization, partner-gate and staff-before-portal checks. The six independent admissions are point-in-time observations, not one cross-connection atomic guarantee. Changes, new sandbox rows, events, email/profile writes or financial activity outside the two narrow exceptions are drift; there is no exclusion for an anticipated app side effect.
