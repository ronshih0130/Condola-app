# B018 Darwin server-group design independent review

**Conditionally sound as a design.** No implementation or runtime approval. The plan and companion JSON remained fixed. All 22 references matched at entry. At final readback the separately authored parent owned.py had changed from 6a832b4a234e5fddb6227320ed511bef137ff11237860d92eb9c064baa858248 to af43989c1f8e608e3d732b150fa21df774ebab46756191bce7eecd8786725963; this opinion covers the proposed invariant and grants no approval to either helper implementation.

The proposed numeric-address invariant is conditionally sound. A direct PID greater than one created as session leader remains reserved while that personal child is alive or retained as a waitable zombie. No other session can create a new group with that reserved PID. This protects group addressing during continuous ownership; it does not prove tree containment or drain.

Use one private opaque server handle, one launch generation and one sole reaper. Retain the strong Popen reference; prohibit poll/wait/communicate/destructor cleanup or another consuming waiter. Close signal authority irrevocably before the sole consuming wait on the exact PID. No signalling after owner loss, ambiguous wait or reaping. Distinguish direct requested TERM, bounded group escalation, natural exit, direct reap and drain. The proposed single-threaded premise is not literally satisfied by an owner using threaded private IPC. Keep a closed single-threaded owner or separately prove all managed I/O threads cannot change signal disposition, wait, or access the handle. Protect launch against interruption without accidentally passing blocked stop signals into the server.

Future separately authorized preflight must positively identify the harmless exact direct child as a retained zombie with matching PPID/group before reaping it exactly once with matching zero status. SIGCHLD disposition alone cannot detect SA_NOCLDWAIT. Probe non-consuming wait support only on the actual pinned OS/interpreter. Missing visibility or ambiguous observation is a failed precondition. A single preflight does not prove that subsequent code preserved the disposition or sole-reaper invariant.

For drain, require the retained terminal anchor and complete bounded membership observation plus a quiescent/closed topology or equivalent atomic proof. Empty/partial samples, one live leader, zero CLI exit and signal success cannot establish drain. Escaped members and separately owned Chromium are outside original-group evidence. If uncertain, preserve GROUP_DRAIN_UNVERIFIED and quarantine without destructive workspace cleanup.

The fixed Next CLI forks and can restart the worker or deliver its own SIGKILL after TERM. The telemetry disabled+debug path synchronously runs the helper without detach and logs metadata privately; pin reachable config and log scope, keep the trace-upload URL absent and upload disabled. This disposes of one branch. Webpack middleware exposes /__nextjs_launch-editor (server/dev/middleware-webpack.js around 397). On Darwin, next-devtools/server/launch-editor.js around 400 can use osascript to ask Terminal to run an independently owned command. Its explicit detached:true branch is Windows-only. Exclude that route before dispatch or pin a reviewed inert editor choice. Account for applicable static-path Jest workers, restart, native/dependency fallback and project config hooks. A browser proxy does not constrain Node subprocesses. Full Next topology is unproved.

Negative controls must cover auto-reaping/competing waits, partial launch, reused numeric IDs, interruption around consuming wait, failed/ambiguous delivery, incomplete census, forced exit with status zero and escaped helpers. No general manager is required. A helper that cannot substantiate these conditions must continue refusing automatic group kills.

No live preflight, census, signal, SQL or browser was exercised. Observer v2 was not reviewed.
